# Deploying LedgerForge to AWS

Infrastructure as code for a production-shaped deployment: Terraform builds the AWS account side, and Kustomize manifests run the two services on Kubernetes. Every change is validated in CI ([`infra.yml`](../.github/workflows/infra.yml)) without touching a cloud account: Kubernetes and CRD schema checks, `terraform validate`, and Trivy misconfiguration scans that fail on any HIGH or CRITICAL finding.

```
deploy/
├── terraform/            AWS: VPC, EKS, RDS PostgreSQL, ElastiCache Redis, ECR, KMS, Secrets Manager, IAM
└── k8s/
    ├── base/             Cloud-neutral: hardened Deployments, Services, HPA, PDB, NetworkPolicies, mTLS certificates
    └── overlays/aws/     EKS specifics: secrets from Secrets Manager, ECR images, ALB ingress, VPC network rules
```

## What gets built

```
                Internet
                   │  HTTPS (TLS 1.2+), /v1 and /oauth only
          ┌────────▼─────────┐
          │ Application LB   │  public subnets (3 AZs)
          └────────┬─────────┘
   ┌───────────────┼──────────────────────── EKS, private subnets ───────────┐
   │      ┌────────▼────────┐  mutual TLS   ┌────────────────┐               │
   │      │ ledger-api x3+  ├──────────────►│ fraud-service  │ accepts only  │
   │      │ (HPA to 12)     │  cert-manager │ x2+            │ the ledger    │
   │      └───┬─────────┬───┘  certificates └────────────────┘               │
   └──────────┼─────────┼──────────────────────────────────────────────────────┘
        TLS   │         │  TLS + auth token
   ┌──────────▼───┐ ┌───▼───────────────┐      ┌──────────────────────────┐
   │ RDS Postgres │ │ ElastiCache Redis │      │ Secrets Manager  ──────► │ External Secrets
   │ 16, Multi-AZ │ │ Multi-AZ          │      │ (KMS-encrypted)          │ Operator → pods
   └──────────────┘ └───────────────────┘      └──────────────────────────┘ (as files)
```

| Area | Controls |
|---|---|
| Network | Private subnets for everything but the load balancer and NAT; database and Redis accept only the EKS nodes' security group; the default security group allows nothing; VPC flow logs kept for a year |
| Kubernetes | Private API endpoint by default; Secrets envelope-encrypted with KMS; control-plane audit logs; IMDSv2 with one hop, so pods can't take the node's AWS credentials; NetworkPolicies enforced by the VPC CNI |
| Workloads | Pod Security "restricted" enforced on the namespace; non-root fixed UIDs, read-only root file system, all capabilities dropped, seccomp; no service-account tokens mounted; resource limits; probes; graceful shutdown with a pre-stop drain |
| Traffic | Default-deny NetworkPolicies. The fraud service accepts only the ledger API and makes no connections. The API reaches the fraud service, PostgreSQL, Redis and HTTPS (Claude API) but never the instance-metadata service |
| Service identity | Mutual TLS between the API and the fraud service, with a CA used for nothing else; certificates last 90 days and are renewed by cert-manager 30 days early |
| Data | RDS: encrypted (customer-managed KMS key), TLS forced (`rds.force_ssl`), the API verifies the server certificate (`sslmode=verify-full`), Multi-AZ, 14-day point-in-time recovery, deletion protection, final snapshot. Redis: encrypted at rest and in transit, auth token |
| Secrets | Generated by Terraform, stored in Secrets Manager, synced by External Secrets Operator, mounted into pods as files (never in Git or environment listings, except the fraud service's token). The operator's IAM role can read only this environment's secrets |
| Supply chain | ECR with immutable tags, scan on push, KMS encryption; images built and scanned by Trivy in CI |
| Exposure | Only `/v1` and `/oauth` are routed from the internet. `/admin` and `/actuator` are reachable only inside the cluster (`kubectl port-forward`) |

## Prerequisites

- An AWS account, Terraform 1.6+, `kubectl`, `helm`, Docker, and the AWS CLI.
- An S3 bucket for Terraform state (versioned, encrypted, with public access blocked). State contains the generated secrets.
- An ACM certificate for your API host name in the same region.

## Steps

**1. Infrastructure**

```bash
cd deploy/terraform
terraform init -backend-config="bucket=<state bucket>" -backend-config="key=ledgerforge/prod.tfstate" \
               -backend-config="region=af-south-1" -backend-config="use_lockfile=true" -backend-config="encrypt=true"
terraform apply -var 'api_hostname=api.yourcompany.com' -var 'acm_certificate_arn=arn:aws:acm:...' \
                -var 'cluster_endpoint_public_access_cidrs=["<your office IP>/32"]'
$(terraform output -raw configure_kubectl)
terraform output -raw kustomize_params > ../k8s/overlays/aws/params.env
```

**2. Cluster add-ons** (once per cluster)

```bash
helm repo add jetstack https://charts.jetstack.io
helm repo add external-secrets https://charts.external-secrets.io
helm repo add eks https://aws.github.io/eks-charts
helm repo add stakater https://stakater.github.io/stakater-charts
helm install cert-manager jetstack/cert-manager -n cert-manager --create-namespace --set crds.enabled=true
helm install external-secrets external-secrets/external-secrets -n external-secrets --create-namespace
helm install reloader stakater/reloader -n reloader --create-namespace
# AWS Load Balancer Controller: needs its own IAM role; follow the AWS guide for your cluster.
```

**3. Images**

```bash
aws ecr get-login-password | docker login --username AWS --password-stdin <account>.dkr.ecr.af-south-1.amazonaws.com
docker build -t <ledger-api repo>:0.3.0 . && docker push <ledger-api repo>:0.3.0
docker build -t <fraud-service repo>:0.3.0 fraud-service && docker push <fraud-service repo>:0.3.0
```

**4. Application**

```bash
kubectl apply -f deploy/k8s/base/namespace.yaml
# RDS certificate authorities, so the API can verify the database (sslmode=verify-full):
curl -sSfo global-bundle.pem https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem
kubectl -n ledgerforge create configmap rds-ca-bundle --from-file=global-bundle.pem
kubectl apply -k deploy/k8s/overlays/aws
kubectl -n ledgerforge rollout status deploy/ledger-api
```

**5. Check it**

```bash
curl https://api.yourcompany.com/v1/accounts -H "Authorization: Bearer <api key>"   # 401 without one
kubectl -n ledgerforge port-forward svc/ledger-api 8080:80 &
curl localhost:8080/actuator/health
```

Create the first tenant through `/admin/tenants` over the port-forward, using the admin token from Secrets Manager (`ledgerforge/prod/app`).

## Operating notes

- **Rotating a secret:** change it in Secrets Manager. External Secrets refreshes within an hour (or annotate the ExternalSecret to force it), and Reloader restarts the pods. For the database password, change it in RDS and Secrets Manager together.
- **Certificates** renew automatically; Reloader restarts both services onto the new ones. The ledger refuses transfers it can't score (`FRAUD_FAIL_OPEN=false`), so a broken certificate shows up immediately as `FRAUD_CHECK_UNAVAILABLE`.
- **Scaling:** the HPAs scale on CPU. The ledger's hot path is row locks in PostgreSQL ([ADR 0002](../docs/adr/0002-pessimistic-locking.md)), so watch database CPU and lock waits before adding API replicas.
- **Assistant:** off by default. To turn it on, add an `anthropic-api-key` secret, map it to `ledgerforge.assistant.api-key` in the ExternalSecret, and set `ASSISTANT_ENABLED=true`.
- **Known gaps, deliberately left for later:** the app connects as the database owner (a separate least-privilege role for runtime is the next step); worker nodes have unrestricted outbound HTTPS through NAT (VPC endpoints and an egress firewall would narrow it); the mTLS CA key lives in the cluster (a managed private CA would move it out).
